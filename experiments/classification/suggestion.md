## PART 1: WHERE WE ARE RIGHT NOW

### What We Have Built

We have built a **learnable additive kernel network** for classification. Instead of applying one
single kernel function to the full feature vector (which is how almost all classical kernel methods
work), our model decomposes the kernel additively across individual features:

```
K(X) = sum over k:  alpha_k * K_k(x_k)
```

Where:
- `K_k` is a small sub-kernel operating on only **one feature at a time** (RBF, Linear, or Polynomial)
- `alpha_k` is a **learned weight** saying how much feature k matters
- The sub-kernel parameters (gamma for RBF, sigma for Linear) are also learned from data

The model is trained using **kernel alignment loss** — pushing the learned kernel matrix to match
the ideal label-based kernel matrix (same-class pairs should be similar, different-class pairs
should not). Classification is then done via **Kernel Ridge Regression (KRR)** on top of the
learned kernel.

This idea is directly inspired by **Kolmogorov-Arnold Networks (KANs)** — decompose a multivariate
function into a sum of univariate functions, but here in kernel space.

### What We Have Tested So Far

All experiments so far used **synthetic data** generated by us:
- Two moons, concentric circles, Gaussian mixtures
- The "professor generator": a controlled synthetic dataset with known feature blocks
  (shared informative, class-specific informative, and pure noise features)

These synthetic experiments answer:
1. Does accuracy hold up as we add noise features?
2. Do the alpha weights correctly concentrate on informative features?

## PART 3: THE REFERENCE PAPER — WHAT IT DID

### Paper Details

**Title:** "Sparse Multiple Kernel Learning: Alternating Best Response and Semidefinite Relaxations"

**Authors:** Dimitris Bertsimas, Caio de Prospero Iglesias, Nicholas A. G. Johnson
(MIT Operations Research)

**Published in:** Transactions on Machine Learning Research, 2025

**ArXiv link:** https://arxiv.org/abs/2511.21890

**HTML version (free, no login needed):** https://arxiv.org/html/2511.21890

---

### What Problem The Paper Solves

The paper studies **Multiple Kernel Learning (MKL)** — a family of methods where instead of
choosing one kernel, you combine multiple pre-built kernels with learned weights.

Standard MKL gives you a combination like:
```
K_combined = beta_1 * K_1 + beta_2 * K_2 + ... + beta_M * K_M
```

Where each `K_m` is a different kernel (e.g., RBF with different gamma values, or polynomial kernels
with different degrees), all computed on the **full feature vector**.

The paper's specific contribution is making this combination **sparse** — forcing only a few of the
M kernels to have nonzero weights. Their algorithm (called SMKL — Sparse MKL) uses a cardinality
constraint instead of L1 regularization, and solves it via an alternating optimization method backed
by semidefinite programming.

---

### The Benchmark Protocol The Paper Used

The paper benchmarked on exactly **10 UCI binary classification datasets**.

These are standard, publicly available datasets that the MKL community has been using for years.

Here are the 10 datasets with their key properties:

| Dataset         | Samples | Features | Description                                      |
|-----------------|---------|----------|--------------------------------------------------|
| breastcancer    | 569     | 30       | Wisconsin Diagnostic: malignant vs benign tumors |
| ionosphere      | 351     | 34       | Radar signals: good vs bad ionosphere returns    |
| spambase        | 4601    | 57       | Email features: spam vs not spam                 |
| banknote        | 1372    | 4        | Wavelet features from banknote images: real vs fake |
| haberman        | 306     | 3        | Survival after breast cancer surgery             |
| mammographic    | 830     | 5        | Mammogram findings: benign vs malignant          |
| parkinsons      | 195     | 22       | Voice measurements: Parkinson's vs healthy       |

| iris            | 150     | 4        | Flower measurements (binarized to 2 classes)     |
| heart           | 270     | 13       | Clinical data: heart disease vs no heart disease |

All are **binary classification** problems (two classes only). This is important because several
competing MKL methods only support binary classification.

---

### What Kernels The Paper Used As Input

In MKL, you first build a set of "base kernels" — M different kernel matrices, all on the full
feature vector — and then the MKL algorithm learns how to combine them.

The paper used **homogeneous polynomial kernels (HPK)** of degrees 1 through 10 as base kernels.
That means:
```
K_d(x_i, x_j) = (x_i . x_j)^d     for d = 1, 2, 3, ..., 10
```

So M = 10 base kernels in total, one for each polynomial degree.

This is a standard and well-established choice in the MKL literature.

---

### What Methods The Paper Compared Against

These are the **competitor methods** that were benchmarked:

#### 1. AverageMKL
The simplest possible MKL baseline. Just takes the average of all M base kernels:
```
K_combined = (1/M) * sum(K_m)
```
No learning involved. Despite its simplicity, it is surprisingly competitive.

**Library:** MKLpy (pip install MKLpy)

#### 2. EasyMKL
A fast MKL algorithm that maximizes the margin between classes in the combined kernel space.
Solves a convex optimization problem.
**Paper:** Aiolli and Donini, Neurocomputing 2015
**Library:** MKLpy

#### 3. CKA (Centered Kernel Alignment MKL)
Learns kernel combination weights by maximizing alignment between the combined kernel and the
ideal label kernel. Very related conceptually to our alignment loss!
**Library:** MKLpy

#### 4. Their own SMKL method (the paper's contribution)
The sparse combination method using cardinality constraints and alternating best response.
This is what they propose and show outperforms the others.

---

### What Results They Got

The paper reports **out-of-sample accuracy** on each dataset for each method.
Their key result: SMKL with random initialization outperforms the best MKL baseline by
**3.34 percentage points on average**, and with warm starting by **4.05 percentage points**.
The largest gains were on ionosphere, heart, and parkinsons.

### Why This Is Meaningful For Us

Our model is architecturally different from standard MKL:

| Property                     | Standard MKL (EasyMKL etc.)          | Our Model (Additive KNN)              |
|------------------------------|--------------------------------------|---------------------------------------|
| Kernel scope per sub-kernel  | Full feature vector                  | One feature at a time                 |
| What is being combined       | M different full-vector kernels      | p feature-level sub-kernels           |
| Number of kernels combined   | M (typically 10)                     | p (= number of features)              |
| Training objective           | Margin maximization / alignment      | Kernel alignment (same idea as CKA!)  |
| Classifier on top            | SVM                                  | Kernel Ridge Regression               |
| Interpretability             | Which global kernel matters          | Which individual feature matters      |

So our model is not exactly doing the same thing as MKL — it is doing something with a richer
feature-level interpretation. But they are solving the same high-level problem (learn a kernel
combination from data), so the comparison is valid and informative.

### Step 3: Preprocessing

All kernel methods are sensitive to feature scale. Always standardize before computing kernels:

```python
from sklearn.preprocessing import StandardScaler

def preprocess(X_train, X_test):
    scaler = StandardScaler()
    X_train_scaled = scaler.fit_transform(X_train)   # fit ONLY on train
    X_test_scaled  = scaler.transform(X_test)         # apply same scaler to test
    return X_train_scaled, X_test_scaled
```

CRITICAL: Always fit the scaler on training data only. Never fit on test data.

### Step 5: Build Base Kernels for MKL Methods

MKL methods need a **list of kernel matrices** as input (one per base kernel).
Following the paper, we use homogeneous polynomial kernels of degrees 1 to 10:

```python
import numpy as np

def compute_hpk_kernels(X_train, X_test, degrees=range(1, 11)):
    """
    Compute Homogeneous Polynomial Kernels: K_d(x,z) = (x dot z)^d
    Returns:
        KL_train: list of (n_train x n_train) numpy arrays
        KL_test:  list of (n_test x n_train) numpy arrays
    """
    gram_train = X_train @ X_train.T       # (n_train, n_train)
    gram_test  = X_test  @ X_train.T       # (n_test, n_train)

    KL_train = []
    KL_test  = []
    for d in degrees:
        KL_train.append(gram_train ** d)
        KL_test.append(gram_test  ** d)

    return KL_train, KL_test
```

### Step 6: Run MKL Baselines

```python
import torch
import numpy as np
from sklearn.metrics import accuracy_score
from MKLpy.algorithms import AverageMKL, EasyMKL, CKA

def run_mkl_baselines(KL_train, KL_test, y_train, y_test):
    """
    Runs AverageMKL, EasyMKL, CKA on the given kernel lists.
    Returns dict of {method_name: accuracy}.
    MKLpy requires labels as -1/+1 and kernel matrices as torch tensors.
    """
    KL_train_t = [torch.tensor(K, dtype=torch.float64) for K in KL_train]
    KL_test_t  = [torch.tensor(K, dtype=torch.float64) for K in KL_test]
    y_train_t  = torch.tensor(y_train, dtype=torch.float64)

    results = {}

    # AverageMKL
    try:
        model = AverageMKL().fit(KL_train_t, y_train_t)
        y_pred = model.predict(KL_test_t)
        results["AverageMKL"] = accuracy_score(y_test, y_pred.numpy())
    except Exception as e:
        results["AverageMKL"] = None
        print(f"    AverageMKL failed: {e}")

    # EasyMKL
    try:
        model = EasyMKL(lam=0.1).fit(KL_train_t, y_train_t)
        y_pred = model.predict(KL_test_t)
        results["EasyMKL"] = accuracy_score(y_test, y_pred.numpy())
    except Exception as e:
        results["EasyMKL"] = None
        print(f"    EasyMKL failed: {e}")

    # CKA
    try:
        model = CKA().fit(KL_train_t, y_train_t)
        y_pred = model.predict(KL_test_t)
        results["CKA"] = accuracy_score(y_test, y_pred.numpy())
    except Exception as e:
        results["CKA"] = None
        print(f"    CKA failed: {e}")

    return results
```

### Step 8: Run Our Model

This wraps our existing training pipeline for use on real UCI datasets.
Adjust import paths to match your actual project structure.

```python
import torch
import numpy as np
from sklearn.metrics import accuracy_score
import sys
sys.path.insert(0, ".")   # run from project root

from kernel_learning.kernel_network.network import KernelNetwork
from kernel_learning.sub_kernels.rbf import RBFSubKernel
from kernel_learning.losses.alignment import AlignmentLoss
from kernel_learning.trainers.manual_gradient import ManualGradientTrainer
from kernel_learning.methods.KernelRidgeClassifier import KernelRidgeClassifier


def run_our_model(X_train, X_test, y_train, y_test,
                  epochs=500, lr=0.01, lambda_ridge=1e-4):
    """
    Trains our additive kernel network and evaluates on test set.
    Returns (accuracy, final_alpha_weights).
    """
    p = X_train.shape[1]

    X_train_t = torch.tensor(X_train, dtype=torch.float32)
    X_test_t  = torch.tensor(X_test,  dtype=torch.float32)
    y_train_t = torch.tensor(y_train, dtype=torch.long)

    # Build model: one RBF sub-kernel per feature
    sub_kernels = [RBFSubKernel() for _ in range(p)]
    model = KernelNetwork(
        sub_kernels=sub_kernels,
        alpha_constraint="square",
        normalize_alphas=True,
        alpha_init="random"
    )

    # Train with alignment loss
    loss_fn = AlignmentLoss()
    trainer = ManualGradientTrainer(model, loss_fn, lr=lr)
    trainer.train(X_train_t, y_train_t, epochs=epochs)

    # Evaluate with KRR
    clf = KernelRidgeClassifier(lambda_ridge=lambda_ridge)
    clf.fit(model, X_train_t, y_train_t)
    y_pred = clf.predict(model, X_train_t, X_test_t)

    acc    = accuracy_score(y_test, y_pred.numpy())
    alphas = model._get_alphas().detach().numpy()

    return acc, alphas
```

Paste all the above functions into one file, then run this main loop:

```python
import numpy as np
import json
from sklearn.model_selection import StratifiedShuffleSplit
from sklearn.preprocessing import StandardScaler

ALL_DATASETS = [
    "breastcancer", "ionosphere", "spambase", "banknote",
    "haberman", "mammographic", "parkinsons", "wine", "iris", "heart"
]

N_SPLITS     = 5       # number of independent train/test splits per dataset
TEST_SIZE    = 0.2     # 80% train, 20% test
RANDOM_SEED  = 42      # fixed seed for reproducibility
EPOCHS       = 500     # training epochs for our model
LR           = 0.01    # learning rate for our model
LAMBDA_RIDGE = 1e-4    # KRR regularization

all_results = {}

for dataset_name in ALL_DATASETS:
    print(f"\n{'='*60}")
    print(f"  Dataset: {dataset_name}")
    print(f"{'='*60}")

    X, y = load_uci_dataset(dataset_name)
    print(f"  Shape: {X.shape}   Class balance: +1={( y==1).sum()}  -1={(y==-1).sum()}")

    sss = StratifiedShuffleSplit(n_splits=N_SPLITS, test_size=TEST_SIZE, random_state=RANDOM_SEED)
    split_results = []

    for split_idx, (train_idx, test_idx) in enumerate(sss.split(X, y)):
        print(f"\n  --- Split {split_idx+1}/{N_SPLITS} ---")

        X_train_raw, X_test_raw = X[train_idx], X[test_idx]
        y_train,     y_test     = y[train_idx], y[test_idx]

        # Standardize
        scaler  = StandardScaler()
        X_train = scaler.fit_transform(X_train_raw)
        X_test  = scaler.transform(X_test_raw)

        # Build HPK base kernels for MKL methods
        KL_train, KL_test = compute_hpk_kernels(X_train, X_test, degrees=range(1, 11))

        # Run all methods
        mkl_res = run_mkl_baselines(KL_train, KL_test, y_train, y_test)
        svm_res = run_svm_baselines(X_train, X_test, y_train, y_test)
        our_acc, our_alphas = run_our_model(
            X_train, X_test, y_train, y_test,
            epochs=EPOCHS, lr=LR, lambda_ridge=LAMBDA_RIDGE
        )

        print(f"    AverageMKL : {mkl_res.get('AverageMKL', 'N/A')}")
        print(f"    EasyMKL    : {mkl_res.get('EasyMKL',    'N/A')}")
        print(f"    CKA        : {mkl_res.get('CKA',        'N/A')}")
        print(f"    SVM_RBF    : {svm_res.get('SVM_RBF',    'N/A')}")
        print(f"    SVM_Linear : {svm_res.get('SVM_Linear', 'N/A')}")
        print(f"    OurModel   : {our_acc:.4f}")

        split_results.append({
            "split"     : split_idx,
            "AverageMKL": mkl_res.get("AverageMKL"),
            "EasyMKL"   : mkl_res.get("EasyMKL"),
            "CKA"       : mkl_res.get("CKA"),
            "SVM_RBF"   : svm_res.get("SVM_RBF"),
            "SVM_Linear": svm_res.get("SVM_Linear"),
            "OurModel"  : float(our_acc),
            "our_alphas": our_alphas.tolist()
        })

    # Aggregate over splits
    methods = ["AverageMKL", "EasyMKL", "CKA", "SVM_RBF", "SVM_Linear", "OurModel"]
    summary = {}
    for method in methods:
        vals = [r[method] for r in split_results if r.get(method) is not None]
        if vals:
            summary[method] = {"mean": float(np.mean(vals)), "std": float(np.std(vals))}

    all_results[dataset_name] = {"splits": split_results, "summary": summary}

    print(f"\n  SUMMARY ({dataset_name}):")
    for m, s in summary.items():
        print(f"    {m:15s}: {s['mean']:.4f} +/- {s['std']:.4f}")

# Save to file
with open("benchmark_results.json", "w") as f:
    json.dump(all_results, f, indent=2)
print("\n\nAll results saved to benchmark_results.json")
```

## PART 6: WHAT EACH METHOD IS — PLAIN ENGLISH SUMMARY

### AverageMKL
Just averages 10 polynomial kernels (degree 1 through 10), all on the full feature vector.
No learning, just equal averaging. Acts as a simple ensemble baseline.
Surprisingly competitive in practice.

### EasyMKL
Learns the combination weights for the 10 polynomial kernels by maximizing the SVM margin
in the combined kernel space. One convex optimization step. Fast and effective.

### CKA (Centered Kernel Alignment)
Learns kernel combination weights by maximizing alignment between the combined kernel and
the ideal label kernel (same-class pairs aligned, different-class pairs not).
This is conceptually the CLOSEST to our model — we use alignment loss too!
The key difference: CKA combines full-vector polynomial kernels,
while we combine per-feature RBF sub-kernels.

### SVM_RBF
Standard single-kernel RBF support vector machine on the full feature vector.
The universal baseline everyone uses.

### SVM_Linear
Standard linear SVM on the full feature vector.
Very strong on well-scaled tabular data.

### Our Model (Additive Kernel Network + KRR)
One RBF sub-kernel per feature dimension. Learned alpha weights via alignment loss.
KRR classifier on top. The key difference from all of the above:
operates at the **feature level**, not the full-vector level.
This means it can selectively ignore uninformative features,
which is our main architectural advantage.

## PART 7: POTENTIAL ISSUES AND HOW TO HANDLE THEM

### Issue 1: MKLpy or cvxopt installation fails

On Windows, cvxopt often fails via pip. Use conda:
```bash
conda install -c conda-forge cvxopt
pip install MKLpy
```

On Mac with Apple Silicon:
```bash
pip install cvxopt --no-binary cvxopt
pip install MKLpy
```

### Issue 2: ucimlrepo fetch fails (network issue or ID changed)

For breastcancer and iris, use sklearn's built-in loaders as fallback:
```python
from sklearn.datasets import load_breast_cancer, load_iris

# breastcancer fallback
data = load_breast_cancer()
X, y_raw = data.data, data.target
y = np.where(y_raw == 0, 1, -1)    # 0=malignant -> +1

# iris fallback (binarized)
data = load_iris()
X, y_raw = data.data, data.target
y = np.where(y_raw == 0, 1, -1)    # setosa vs rest
```

For the remaining datasets, download CSV files directly from:
https://archive.ics.uci.edu/datasets
and load with pandas.

### Issue 3: wine and iris have 3 original classes

Both have been binarized in the loading code above.
wine:  class 1 vs classes 2 and 3
iris:  Iris-setosa vs Iris-versicolor + Iris-virginica

### Issue 4: mammographic has missing values (~8% of rows)

Already handled in the loading code with pandas dropna().
Expected final size: approximately 830 samples.

### Issue 5: spambase is large (4601 samples)

Full-batch kernel computation is O(n^2) in memory.
For a machine with limited RAM, reduce training set size:
```python
# Use only 1000 training samples for spambase
from sklearn.model_selection import StratifiedShuffleSplit
sss_sub = StratifiedShuffleSplit(n_splits=1, test_size=0.8, random_state=0)
sub_idx, _ = list(sss_sub.split(X_train, y_train))[0]
X_train = X_train[sub_idx]
y_train = y_train[sub_idx]
```

### Issue 6: MKLpy expects exactly -1/+1 labels

Always verify before passing to MKLpy:
```python
assert set(np.unique(y_train)) == {-1, 1}, "Labels must be exactly -1 and +1"
```

### Issue 7: EasyMKL or CKA fails on a specific dataset

Some datasets cause numerical issues in MKL solvers. Options:
- Try different `lam` values for EasyMKL: 0.0, 0.01, 0.1, 0.5
- Skip that method for that dataset and record as N/A
- The benchmark still works with partial results
